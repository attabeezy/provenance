# provenance

Reproducibility codebase for the position paper "Authorship Needs Provenance, Not
Prediction" (authors withheld).

The paper argues that AI-text detection, a prediction over the finished artifact,
cannot serve as evidence in authorship disputes. Disputes need provenance: process
records, disclosure contracts, attestations, and audit. Four experiments support the
argument, and every number they produce is recomputable from this repository. The
paper draft and its builds live in a local `paper/` folder that is deliberately not
versioned here.

## Repository layout

```
src/provenance/          the code (single source of truth for paths: provenance/paths.py)
  features.py            marker suite: 32-item slop lexicon, em-dash, triads, not-X-but-Y, stats
  corpora.py             jsonl IO + loaders for the eight comparison corpora
  collect.py             networked collectors: Hacker News, arXiv cs.CL, Gutenberg; HF downloads
  extract.py             derived corpora: wiki pairs, HC3 pairs, per-document feature caches
  experiments/           E1 time series, E2 marker overlap, E3 detector grid, E4 arithmetic,
                         meta-audit (the paper scores itself), shared detector utils
tests/                   pytest: feature correctness on synthetic text, detector smoke
analysis/                committed result JSONs (e1_summary, e2_overlap, e3_detector, e4_math, ...)
figures/                 committed figures (png+pdf), regenerated by E1/E2/E3/E4
data/raw/                gitignored raw corpora (~280 MB); re-downloadable (see below)
references/              the two source documents styled after: the ACM AI Letters paper (3830910)
                         and Jerry Wei's Stanford application
```

## Setup

Requires Python >= 3.12.

```powershell
pip install -e ".[test]"
python -m pytest          # 14 tests, no data required
```

## Data pipeline

All raw corpora are gitignored and re-downloadable/derivable:

| corpus | how to obtain |
|---|---|
| Hacker News comments | `prov collect hn` (Algolia API; ~1.5 h) |
| arXiv cs.CL abstracts | `prov collect arxiv` (export API, 6 s/request; ~1 h) |
| Gutenberg classics | `prov collect gutenberg` (title/author self-verifying) |
| GPT-wiki-intro zip | `prov download wiki` (HF: `aadityaubhat/GPT-wiki-intro`, file `GPT-wiki-intro.csv.zip`) |
| HC3 all.jsonl | `prov download hc3` (HF: `Hello-SimpleAI/HC3`, file `all.jsonl` — casing matters) |
| derived pairs | `prov extract wiki`, `prov extract hc3` |
| feature caches | `prov extract feats` (writes `analysis/feat_*.jsonl`) |

Signing in to Hugging Face is not required: both datasets are ungated.

## Experiments

```powershell
prov run e1        # marker time series (HN + arXiv), writes analysis/e1_timeseries.json
prov run e1fig     # Figure 1 + e1_summary.json
prov run e1report  # printable E1 table
prov run e2        # marker overlap across 8 corpora + Figure 2
prov run e3        # classifier grid (folk / tfidf / char x W/H pairs); ~20 min
prov run e4        # posterior + scale arithmetic + Figure 4 (needs e3)
prov run meta      # meta-audit: the paper scores its own draft (needs the local
                   # paper/draft.md, kept outside the repo)
```

Determinism: seeds are fixed (`random_state=13` for all splits, `random.seed(13)` in
the cache builder). Re-running E1-E4 reproduces the committed `analysis/*.json`
byte-for-byte.

## Notes

- HN/arXiv/Gutenberg collectors follow each site's rate limits (1-6 s sleeps); be
  patient or restrict year ranges (`prov collect arxiv 2024 2025`).
- The two cloned source corpora (GPT-wiki-intro 2023 snapshot, HC3 human answers) are
  treated as two points in AI style space, not ground truth for "all AI".
